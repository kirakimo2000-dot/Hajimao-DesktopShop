# Hajimao DesktopShop 可玩 Demo 收敛计划

## 产品判断

截至 0.1.16，项目拥有稳定模拟、存档、挂机、员工、采购、成长、街区和像素表现，但仍是技术样机，不是可玩 Demo。主要问题不是内容少，而是内部系统直接暴露给玩家：七个管理页面、逐商品采购、逐员工排班、逐对象快捷操作共同制造维护负担，却没有形成高价值的投资决策。

第一个可玩 Demo 不再以“系统数量”或“一小时内通关”验收。首个游玩时段只负责让玩家理解经营与完成早期投资；Demo 还必须证明玩家在多次离开、回归和挂机结算后，仍有可达的新目标、资金取舍和店铺成长，而不是在 30～60 分钟内耗尽内容。

## 0.1.20 状态边界

0.1.20 的代码目标是 **Playable Demo Candidate 1**，不是未经观察就宣布完成的 Demo 1。自动门禁已覆盖四步新手投资闭环、三论点跨店资本配置、只读离线回归简报、正式存档/离线/第二家店/弱店投资链路，以及高周转、高毛利、稳健现金三路线的 1、7、30、90 经营日连续性。

这些门禁证明系统可达、确定且不会靠倍速或测试注资运行，但不能证明陌生玩家看得懂。三轮真实陌生玩家测试和跨真实日回访仍是外部门禁；完成前，README、阶段报告和 Release 只能使用 Candidate 名称。执行方法与空白记录见 `docs/playtests/v0.1.20-blind-test-protocol.md`。

## 玩家身份

玩家是投资经营者，不是收银员、补货员或排班员。

玩家负责：

- 判断店铺为什么赚钱或亏钱。
- 在商品策略、人员效率和店铺能力之间配置有限资金。
- 接受短期现金压力，换取可解释的长期回报。
- 观察自动运营结果并在合适时机调整方向。

系统负责：

- 员工任务分配、休息和日常排班。
- 按经营策略选择采购时机、数量和渠道。
- 日常补货、收银、清洁、导购与保存。
- 把经营因果投影到店内人物、顾客和财务反馈。

## 核心循环

`观察经营 → 找出瓶颈 → 选择投资 → 自动运营 → 比较回报 → 再投资或扩店`

早期开店阶段可以每 3～8 个现实分钟出现一次帮助理解系统的判断；店铺稳定后，决策间隔应自然扩大到一次或多次挂机回归。成熟阶段的价值来自“先配置长期策略，再观察跨日复利与瓶颈迁移”，而不是持续提醒玩家点击。游戏继续固定现实 `1x`，挂机价值来自策略持续生效，而不是倍速或离线奖励倍率。

## 成长时间尺度

- **首次接触**：玩家能理解当前盈亏、瓶颈和下一笔投资，但不要求在首小时解锁全部核心成长。
- **早期经营**：通过若干完整日结完成第一轮策略—投资—回报，建立稳定而非必胜的现金流。
- **多次回归**：离开并重新打开游戏后，挂机结果改变可用资金、库存与投资取舍；第二家店是长期扩张节点，不是教程结束按钮。
- **街区成长**：多店共享资金和客流，玩家持续在“强化成熟店、挽救弱店、开新店”之间配置资本。
- **长期上限**：等级、店铺成长成本和多店组合必须留出跨多个真实日的提升空间；达到一个阶段目标后仍有下一层可见目标，不以倍速、重置刷取或无限点击延长时长。

## 最小决策面

管理窗口只保留三个玩家入口：

1. **经营概览**：收入、毛利、工资、运营费、净利润、现金安全线、顾客流失与当前瓶颈。
2. **经营策略**：店级定价定位与库存投入策略；一次选择作用于整家店，不逐 SKU 重复点击。
3. **投资决策**：比较人员、货架、扩建、装修等候选项目的成本、预期改善与回收期，再选择下一笔投入。

商业街属于场景导航，不再作为经营模块页。货架和员工仍可点击查看原因与状态，但不再提供快速进货、自动补货开关、培训、白班、夜班等日常操作按钮。

## 系统处置矩阵

| 现有系统 | 处置 | 玩家最终看到的形式 |
| --- | --- | --- |
| 逐商品 ±¥0.10 调价 | 合并 | 全店“高周转 / 均衡 / 高毛利”定价定位 |
| 三采购渠道逐次下单 | 自动化 | 库存策略自动选择时机、目标量和渠道 |
| 逐商品自动补货开关 | 合并 | 全店“精益 / 均衡 / 充足”库存投入 |
| 员工任务优先级 | 保留并隐藏操作 | 场景与详情只读显示当前任务和瓶颈 |
| 白班/夜班逐员排班 | 自动化 | 系统按营业需求安排，玩家只控制人工投入 |
| 逐员培训 | 合并 | “人员投资”自动选择当前瓶颈岗位或明确候选 |
| 候选人手动刷新 | 自动化 | 候选池按经营周期更新，不消耗注意力 |
| 扩建/货架/装修 | 保留 | 统一进入投资候选，展示成本与回收期 |
| 三种促销按钮 | 暂时隐藏 | 以后作为有期限、有风险的投资机会重新加入 |
| 独立财务页 | 合并 | 关键比率常驻经营概览，详细报告作为次级展开 |
| 场景对象快捷操作 | 移除 | 点击只负责解释库存、员工与顾客状态 |
| 商业街管理页 | 移出管理导航 | 桌面街区本身承担选店和扩店反馈 |

底层服务不因界面收敛而合成一个巨型管理器。采购、员工、成长、模拟和持久化继续通过明确接口协作；0.1.17 先移除玩家入口，再根据真实调用关系删除无用的 UI 协调代码。

## 经济表达

每家店至少持续公开以下数值，并区分“经营收益”和“现金流”：

- 营业收入。
- 销售毛利与毛利率。
- 工资、运营费用和净利润率。
- 采购现金支出与当前库存占用资金。
- 顾客数、成交数、流失数和流失原因。
- 现金安全线：当前现金可覆盖多少个最近经营周期的必要支出。
- 当前主要瓶颈：缺货、客流、结账、服务或成本。

投资报价必须显示：价格、改变的能力、基于当前经营数据的保守收益估计、预计回收周期和估计不成立的条件。界面不显示无法解释来源的综合评分。

## 版本收敛路线

### 0.1.17：核心循环瘦身

- 把七个经营页压缩为经营概览、策略、投资三个入口。
- 全店定价定位替代逐商品微调。
- 全店库存策略替代逐商品采购和补货开关。
- 隐藏排班、培训、候选刷新和场景快捷维护操作。
- 建立毛利率、净利率、现金安全线和经营瓶颈的只读分析。
- 不增加商品、角色、店铺主题或新美术资源，不升级存档 schema。

出口条件：新店采用默认策略即可自行运营；玩家只做两项店级策略选择和低频投资，不执行日常补货与排班。

### 0.1.18：投资与回报

- 把现有人员、货架、扩建和装修能力统一为投资候选。
- 使用当前经营数据生成保守回报与回收周期，不承诺虚假精度。
- 建立现金安全线和投资后资金压力提示。
- 每项投资都必须改变一个可观察瓶颈，并能在后续报告中比较投资前后表现。

出口条件：玩家可以仅凭概览理解店铺为什么赚钱，并在至少三种有效投资路线中作出有取舍的选择。

### 0.1.19：目标、节奏与平衡

- 把首轮引导与长期成长拆开：引导只教授观察、策略、投资和回报，成长目标继续覆盖跨日经营、多次回归和多店资本配置。
- 建立首次接触、早期单店、多次回归、第二家店、完整街区五段成长标尺；30～60 分钟只作为早期可理解性观察窗口，不作为游戏寿命。
- 调整开局现金、需求、工资、采购、经验、开店与升级成本，消除必胜、死档、首小时毕业和后期无目标。
- 建立 1、7、30 个经营日以及多次离线回归的确定性进度情景，验证资金、等级、投资与店铺数量仍按可解释速度成长。
- 增加失败恢复：亏损诊断、保守策略和现金保护，不赠送无条件收益。

出口条件：新玩家能快速理解下一步，早期投资不会导致必胜或永久死档；长期情景不会在首个游玩时段耗尽成长，也不会在多次回归后只剩无意义等待。

### 0.1.20：Playable Demo Candidate 1

- 完成只服务核心循环的界面与像素反馈。
- 准备至少三轮新存档首次接触和跨真实日回访协议；取得真实记录后再修正理解阻塞并决定是否晋级 Demo 1。
- 确保存档、离线运营、反复重新打开、第一家店成长、第二家店扩张和街区后续目标形成连续体验。
- 通过 1、7、30 个经营日的自动情景门禁，确认不同经营路线不会过早封顶、无限滚雪球或永久停滞。
- 冻结 Demo 的商品和美术资源范围，不以增加内容掩盖数值或节奏问题。

出口条件见下方硬门禁；任一项不满足，版本不得称为可玩 Demo。

## Playable Demo 1 硬门禁

### 自动门禁（0.1.20 Candidate 已覆盖）

- 正式生产入口能连续完成新档、整店策略、首个日结、首次投资、下一日回报比较、保存、三次离线返回、第二家店和弱店投资。
- 1、7、30、90 个经营日的确定性情景保持现金非负、工资可支付、三条策略有不同取舍，并在第 90 日仍保留资本选择。
- 存档重开与离线结算复用正常模拟管线；固定现实 `1x`，不存在暂停、倍速、点击收益或测试注资。
- 投资页最多给出稳住弱店、提高回报、扩张街区三个跨店方向；日常采购、排班和员工任务继续自动运行。

### 外部观察门禁（尚未完成）

- 新玩家 3 分钟内能说明“我现在为什么赚钱或亏钱、下一笔钱准备投哪里”。
- 首个游玩时段能独立完成并理解至少一次投资回报，同时清楚看到尚未完成的下一层成长目标。
- 关闭并返回后，能基于现金、成交、净利润和瓶颈变化说明发生了什么，而不是把回归理解成领取线性金币。
- 能理解第二家店和完整街区是资本积累后的跨阶段目标，不会因教程没有立即开店而判断无事可做。
- 场景中的缺货、排队、员工任务和顾客流失对陌生玩家可辨认，并与其读取的财务原因一致。
- 三轮陌生玩家盲测均能独立完成核心循环，没有需要开发者口头解释的阻塞点。

自动条目由测试证据维护；外部条目必须按盲测协议记录真实观察。自动策略 runner 不是玩家盲测，不能用于勾选外部门禁。

## 明确不做

在 Playable Demo 1 之前，不优先增加：

- 新商品数量和复杂供应链阶段。
- 更多员工岗位、人物外观或动画帧。
- 店铺主题、客群、天气种类和街区装饰。
- 成就、活动、社交、排行榜、付费或商业化系统。
- 倍速、点击收益和用繁忙操作伪造参与感的机制。
- 为延长时长而加入、但不改变经营选择的空壳等级、每日签到或强制重置。

只有当一个新模块能强化“观察—投资—回报”循环，并且不能由现有模块合并或自动化时，才允许进入路线图。
