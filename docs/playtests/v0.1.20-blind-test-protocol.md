# Hajimao DesktopShop 0.1.21 陌生玩家盲测协议

## 当前状态

0.1.21 在完成本协议要求的三轮真实观察前，只能称为 **Playable Demo Candidate 1**。本文件是执行协议和空白记录模板，不包含参与者、结果或通过结论；不得用自动测试、开发者自测、反馈 ZIP 或虚构记录替代陌生玩家证据。

## 测试目标

验证没有接触过项目的玩家能否独立理解并完成：

`观察盈亏 → 选择整店策略 → 投资 → 等待完整日结 → 比较回报 → 离开并返回后决定下一步`

第二家店是长期观察项，不要求在首次接触时强行解锁。测试重点是玩家是否理解投资经营因果，而不是点击速度或短时通关。

## 参与者与轮次

- 共三轮，每轮使用一名此前未看过 Hajimao DesktopShop、未参与开发的玩家。
- 每轮建立独立 Windows 用户数据或清空测试专用存档，必须从默认新档开始。
- 参与者以 P1、P2、P3 编号；不在仓库记录姓名、联系方式或其他个人信息。
- 同一参与者的修复后复测可用于诊断，不能替代新的独立盲测轮次。

## 主持人边界

启动游戏后只说一句：

> 经营这家桌面小店。

除系统故障、安全问题或参与者明确结束测试外，主持人不得解释按钮、数值、目标、投资方法、挂机收益或正确答案。参与者提问时只记录原话和时间，不作教学。若必须提供口头帮助，该轮记录为“出现阻塞”，不能判定通过。

## 执行流程

### A. 首次接触

1. 使用 0.1.21 Candidate 的干净便携包和独立新存档启动游戏。
2. 从第一眼看到桌面街区开始计时，并记录首个主动操作、误操作和犹豫位置。
3. 到 3 分钟时只问两题：
   - “这家店现在为什么赚钱或亏钱？”
   - “你的下一笔钱准备投到哪里，为什么？”
4. 继续观察，直到玩家看到第一次投资后的后续完整日结，或明确表示无法继续。
5. 记录玩家是否独立完成非默认整店策略、第一次投资，以及是否能用自己的话说明投资前后变化。

### B. 真实挂机返回

1. 保持程序运行，让玩家离开桌面或只保留挂机页，不提前说明预期收益。
2. 至少经过一个真实的挂机时段后回到经营页；跨真实日观察优先。
3. 询问：“挂机期间发生了什么，你接下来准备关注什么？”
4. 记录玩家是否区分现金变化、成交、净利润和弱店瓶颈，并能否找到下一笔资本方向。
5. 若自然达到第二家店，继续观察跨店投资；不得为了赶流程提供资金、倍速、开发者命令或操作提示。

### C. 反馈包回传

1. 每轮观察结束后，让测试者右键通知区域图标并选择 `生成测试反馈包`。
2. 回传桌面生成的 ZIP 与主持人观察笔记；ZIP 文件名、参与者编号和提交哈希可以记录，参与者姓名、联系方式、Windows 用户名或机器路径不得记录进仓库。
3. ZIP 应只包含 `feedback.json` 与说明文件；内容为版本、schema、聚合经营快照和脱敏事件头，不包含 `hajimao.db`、原始日志、个人路径、机器路径、员工/顾客身份或商品明细。

## 判定标准

每一轮同时满足以下条件才算通过：

- 3 分钟时能指出至少一个来自界面的真实盈亏原因，并给出一项有理由的资金方向。
- 无主持人口头教学，能完成一次整店策略调整和第一次投资。
- 在后续完整日结出现后，能说明至少一项投资前后变化或明确知道仍在等待证据。
- 关闭并返回后，能从回归简报说明发生了什么，并找到下一步关注点。
- 能在结束时生成并回传桌面反馈 ZIP，且不需要提供姓名、联系方式或本机路径。
- 没有被逐商品、逐员工、倍速、领取奖励或开发者工具等不存在的流程卡住。

三轮必须全部通过，0.1.22 才能从 Candidate 晋级为 **Playable Demo 1**。任一轮出现阻塞时，应先保留失败记录、建立可复现问题、修复并重新构建，再邀请新的陌生玩家补足通过轮次；不得改写失败记录。

## 自动门禁与盲测的区别

自动测试负责证明正式生产入口可以完成投资回报、冻结式保存/恢复、多店扩张、弱店投资，以及 1、7、30、90、180、365 个运行中经营日仍然有界且有成长选择。它不测量理解、注意力、措辞歧义或视觉可发现性，因此自动测试通过只能授予 Candidate 状态。反馈 ZIP 只提供排查材料，同样不能替代观察结论。
