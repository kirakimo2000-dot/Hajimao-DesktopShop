# 正式版本序列校正：统一为 0.1.x

## 原因

当前项目仍处于同一个早期开发阶段。此前把多店、挂机存档和采购分别标为 `0.2.0`、`0.3.0`、`0.4.0`，会错误暗示产品已经跨过多个次版本。用户确认这些底层迭代都应属于 `0.1.x`。

## 正式版本映射

| 阶段 | 原正式标签 | 校正后标签 |
| --- | --- | --- |
| 玩法底层 | `0.1.0` | `0.1.0` |
| 多店模拟与经营深度 | `0.2.0` | `0.1.1` |
| 挂机与完整多店存档 | `0.3.0` | `0.1.2` |
| 采购与自动化 | `0.4.0` | `0.1.3` |
| 员工经营 | `0.5.0`（计划） | `0.1.4`（下一步） |

后续单店成长、管理前端、正式像素表现、商业街和发布候选依次使用 `0.1.5`～`0.1.9`；成熟后才发布正式 `1.0.0`。

## 影响范围

- `Directory.Build.props` 当前版本校正为 `0.1.3`。
- 正式 Changelog、路线、阶段报告和实现计划统一改用新编号。
- 正式阶段报告与计划文件同步改名，旧路径不再作为正式路线入口。
- Git 标签将以 `v0.1.1`～`v0.1.3` 取代旧正式标签。
- 游戏规则、测试、存档 schema v4、数据库兼容性和已有提交内容均不改变。
- 原型历史中的旧 `0.1.0`～`1.0.0` 证据保持原样，不参与本次重命名。

## 下一步

从 `0.1.3` 建立 `0.1.4` 员工经营分支，优先实现招聘、排班、培训、体力、满意度和岗位工作负荷，不提前制作正式 UI。
