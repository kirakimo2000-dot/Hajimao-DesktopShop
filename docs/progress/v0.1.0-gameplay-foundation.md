# 0.1.0 玩法底层阶段总结

日期：2026-08-03
状态：完成

## 本阶段结果

- 正式版本从 0.1.0 开始；原 1.0.0 作为原型历史保留。
- 经营固定为现实 1x，活动代码不再暴露暂停或倍速。SQLite schema v2 可迁移带 0/1/2/4 历史速度的 v1 存档，并保留其余数据。
- 新增玩家累计经验与等级曲线。玩家从 1 级、一个起始店铺开始，等级控制商品和新店开放。
- 新增多店组合与共享业务钱包。开店失败保持原子性，各店收入、库存成本和毛利分别统计。
- 商品公开单位毛利和整数毛利率；10 种商品按 1–6 级分批解锁并保持差异化利润。
- 员工具有岗位、效率千分比和小时工资；任务耗时向上取整，工资用分钟余数精确累计。
- 新增多店业务应用服务，统一处理销售经验、升级解锁和开店。
- 新增 Windows 通知区域常驻壳；两个窗口不显示普通任务栏按钮，隐藏窗口不停止模拟或自动存档。

## 架构边界

- 玩家、店铺组合、共享钱包、商品经济和员工规则位于 Domain。
- 跨聚合用例与不可变快照位于 Application。
- SQLite 只负责兼容迁移和持久化；WPF 只负责窗口/托盘适配。
- 现有单店 `ShopGameService` 暂作原型 UI 适配器。0.1.0 的多店与等级能力没有提前塞入旧管理页。

## 验证证据

- `dotnet test HajimaoDesktopShop.slnx -c Release`：76 passed，0 failed。
- `dotnet build HajimaoDesktopShop.slnx -c Release --no-restore`：0 warnings，0 errors。
- 10 个项目执行 `dotnet list ... package --vulnerable --include-transitive`：没有已知漏洞。
- 速度引用扫描：活动源码仅 `LegacyGameSaveV1.Speed` 保留迁移字段；其余命中为“不得含 Speed”的反射测试。
- Release 桌面进程启动后保持响应、无主窗口标题；托盘服务测试确认图标从创建到释放的生命周期，窗口测试确认 `ShowInTaskbar=False`。

## 已知边界

- 当前自动化无法定位仅存在于 Windows 通知区域的界面，因此托盘菜单的逐项鼠标点击仍需一次人工验收。
- 托盘暂用系统应用图标；正式像素图标属于 0.1.7 资产阶段。
- 多店同时模拟、工资实际扣款、逐店需求和完整多店存档属于后续版本，不在 0.1.0 内。

## 下一步：0.1.1

1. 让所有已开店铺进入同一个确定性 Tick 管线。
2. 建立价格、服务、队列、整洁度和时段对需求的可解释模型。
3. 将员工效率用于真实任务，将工资纳入共享钱包与逐店净利润。
4. 增加日结和逐店经营反馈，并保持纯玩法/API 优先，不提前制作正式管理前端。
