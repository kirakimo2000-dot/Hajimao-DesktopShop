# Hajimao DesktopShop 0.1.11 顾客分段行为阶段报告

## 结果

0.1.11 把店内顾客从“队列数量对应的往返人物”深化为完整六阶段旅程：进店、寻找货架、拿取商品、加入队列、结账和离店。顾客依据商品快照走向常温、冷藏或冷冻货架，位置按 125 ms 表现帧连续变化，并继续使用 0.1.10 已交付的八帧人物图集。

## 模块边界

- `BusinessShopCustomerChoreography` 是 Rendering 内的纯函数，只接收货架类型、表现帧、角色种子和减少动态效果设置。
- `CustomerJourneyPose` 只包含阶段、整数像素坐标和是否携带商品，不持有 Domain 实体或可变经营状态。
- `BusinessShopSceneRenderer` 从不可变 `BusinessSimulationSnapshot` 选择稳定商品并绘制路径；WPF 不计算路径，Application/Domain 不知道像素坐标。
- 顾客旅程是经营结果的只读视觉投影，不驱动销量、需求、排队、工资、经验或离线收益。

## 六阶段路径

| 表现帧 | 阶段 | 行为 |
| --- | --- | --- |
| 0–15 | Entering | 从右侧入口进入店内 |
| 16–39 | SeekingShelf | 走向商品所属货架 |
| 40–47 | PickingProduct | 在货架前拿取商品并显示携带标记 |
| 48–63 | JoiningQueue | 从货架走向收银队列 |
| 64–79 | CheckingOut | 向收银台移动并停留结账 |
| 80–95 | Leaving | 放下商品标记并从右侧出口离店 |

三类货架中心分别为常温 `x=110`、冷藏 `x=214`、冷冻 `x=318`。所有移动使用整数插值，避免像素画面出现亚像素模糊。旅程人物与既有排队人物共享最多 5 名顾客的表现预算。

## 已知差距

- 当前旅程是根据累计访客与商品快照生成的稳定视觉投影，不是逐顾客持久化的经济实体；这样避免未经确认改变顾客到店和结算时序。
- 货架和员工尚不能在店铺画面中直接点击查看详情。
- 各店仍共用基础内部布局和外立面风格，尚未达到参考图中每店差异化门面的丰富度。
- MSI/ZIP 仍未签名，真实证书和更多混合 DPI 热插拔机器证据尚待接入。
