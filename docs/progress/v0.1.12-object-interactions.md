# Hajimao DesktopShop 0.1.12 对象直接交互阶段报告

## 结果

0.1.12 让具体店铺画面从只读展示升级为可直接检查的经营入口。玩家可以在任务栏上方桌面长条或管理窗口的实时店铺场景中点击货架和员工，立即进入对应商品/员工管理页并查看轻量详情。交互不增加暂停或倍速，也不推进游戏时间。

## 模块边界

- `LogicalPixelViewport` 只负责窗口坐标与 420×180/420×280 逻辑像素的整数缩放、居中和边缘拒绝。
- `BusinessShopInteractionMap` 是 Rendering 内的纯函数，只输出货架/员工交互目标，不读取 WPF、不执行 Application 命令。
- `BusinessShopEmployeeChoreography` 同时服务绘制和命中区域，收银员、补货员与支援员工的位置不会出现两套公式。
- 两个 WPF 场景控件只把鼠标位置转换为目标并发出 `ObjectClicked`；窗口负责把事件交给 `MarketViewModel`。
- `MarketViewModel` 从不可变经营快照投影详情，选择对象只改变管理导航和界面选择状态，不改变 Domain 或存档。

## 可见玩法

| 对象 | 点击后页面 | 详情内容 |
| --- | --- | --- |
| 常温/冷藏/冷冻货架 | 商品 | SKU 数、当前/最大库存、缺货数、低库存数、平均毛利 |
| 收银员/补货员/导购/清洁员/店长/采购员 | 员工 | 姓名、岗位、有效效率、工时费、体力、满意度、班次 |

桌面店铺页点击对象会请求打开管理窗口；管理窗口内点击对象会在原窗口切换栏目。切换店铺会清除不属于新店的对象选择，刷新详情使用同一游戏分钟的最新快照。

- 存档 schema 保持 v6；固定现实 1x、离线同管线、共享客流、顾客结算和无限横向街区均未改变。

## 已知差距

- 各店目前仍共用基础内部布局和外立面风格，未达到参考图中连续但差异鲜明的门面丰富度。
- 对象详情当前是只读入口；具体采购、培训、排班等操作继续由既有管理卡执行，避免在桌面长条塞入复杂控件。
- MSI/ZIP 仍未签名，真实证书和更多混合 DPI 热插拔机器证据尚未接入。
