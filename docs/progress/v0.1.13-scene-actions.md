# Hajimao DesktopShop 0.1.13 场景化经营操作阶段报告

## 结果

0.1.13 把 0.1.12 的“点击查看”升级为“点击后直接经营”。玩家点击货架后，可对该货架当前最紧缺商品执行本地快速进货或切换自动补货；点击员工后，可直接培训并安排白班或夜班。操作完成后仍停留在同一对象详情，现金、库存、培训等级和班次立即刷新。

本阶段没有开发签名、硬件矩阵、兼容性或合规功能，也没有增加暂停或倍速。

## 玩法规则

### 货架

- 只在被点击的常温、冷藏或冷冻货架内选择商品。
- 优先级按 `当前库存 / 容量` 从低到高排列；比例相同则按稳定商品 ID 排序，避免每次刷新跳到不同商品。
- “快速进货”复用既有本地批发渠道：每次 5 件、即时到货、按本地批发溢价扣款，并继续受资金和货架容量限制。
- “自动补货”复用既有策略：补货点、目标库存、区域配送和缺货应急供应商规则均未在 UI 中复制。

### 员工

- “培训”复用员工服务的真实培训费用、最高等级和效率成长规则。
- “白班”设为 `08:00–16:00`，“夜班”设为 `17:00–01:00`，继续受单班最长 8 小时规则约束。
- 员工详情实时显示培训等级、效率、工时费、体力、满意度和班次。

### 挂机边界

- 点击、进货、自动补货开关、培训和排班都不推进游戏分钟。
- 游戏继续固定现实 `1x`；收益增长依赖经营选择、员工效率与自动化，而不是速度按钮。

## 模块边界

- `ShelfActionTargetSelector` 是纯快照选择器，不读取 WPF，也不修改库存。
- `ShopObjectActionsViewModel` 只把当前对象转发给既有商品/员工卡命令，完成后请求统一刷新。
- `MarketViewModel` 负责对象详情投影和选择生命周期，不计算采购价格、培训费用或班次合法性。
- `ManagementWindow.xaml` 只绑定动作可见性、命令和可访问名称。
- 采购、资金、容量、自动补货、培训和排班规则仍全部位于 Application/Domain。

## 当前差距

- 货架快捷动作目前自动指向最紧缺商品；若玩家想操作货架内其他 SKU，仍需进入商品卡片。
- 员工可以培训和排班，但对象卡尚未显示“正在收银、前往补货、休息”等当前任务和工作优先级。
- 不同店铺仍共用基础门面与室内布局；差异化外观将在经营身份设计确定后实现，避免只换皮不影响玩法辨识。

## 下一步 0.1.14：员工任务与岗位反馈

1. 从真实模拟快照投影员工当前任务、目标对象、剩余任务时间和休息状态。
2. 为员工增加岗位任务优先级，让玩家决定收银、补货、清洁和导购的处理顺序。
3. 让员工移动与八帧动作由当前任务驱动，而不是只按岗位运行固定路线。
4. 保持固定现实 `1x`，所有优先级与任务状态进入在线/离线同一经营管线。
