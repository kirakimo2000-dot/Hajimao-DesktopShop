# v0.1.18 投资与回报

日期：2026-08-10

## 阶段结果

0.1.18 没有增加商品、角色、店铺主题或新的经营模块，而是把已有的人员、货架、扩建和装修能力收敛为同一个投资决策面。玩家现在能先理解经营瓶颈，再比较投入、保守收益、回收期和现金风险；投资后的下一份完整日结会显示实际变化。

本版本完成了投资闭环底座，但尚不称为 Playable Demo。0.1.19 仍需调整新手目标、首次投资节奏、失败恢复和第二家店解锁，0.1.20 才进入陌生玩家盲测门禁。

## 玩家闭环

`查看经营概览 → 找出瓶颈 → 比较投资候选 → 执行投资 → 固定现实 1x 自动经营 → 查看下一份日结差值 → 再投资或扩店`

- “投资决策”统一呈现扩建店面、升级货架、店铺装修和当前招聘候选人。
- 每个候选显示真实成本、可观察能力变化、投后现金、现金压力、保守日收益、回收期及估算成立条件。
- 候选人按经营日自动刷新，不再要求玩家维护刷新操作。
- 开店仍作为独立的多店成长决策；0.1.18 不提前修改第二家店的节奏和平衡。

## 底层逻辑

### 经营基线

- 优先使用最近完整日结；没有日结时使用开店至今累计值并明确标记证据范围。
- 必要经营支出 = 销货成本 + 工资 + 运营费用，其中销货成本 = 收入 - 毛利。
- 现金续航和投后现金压力都使用同一必要支出基线，不在 Desktop 重复计算。

### 保守回报

- 货架和相关岗位只从已观察到的流失顾客、成交数与单位毛利估计可恢复销售，不凭空增加收益。
- 扩建和装修只在当前需求/排队证据能够支持时估算改善；证据不足时预期收益为 0，回收期显示为未知。
- 人员投资的预期净改善会减去每日 8 小时工资；若净改善不为正，不显示回收承诺。
- 回收期以 0.1 个经营日为单位向上取整：`成本 × 10 ÷ 预期每日净改善`。
- 投后现金少于一个必要经营周期为高风险，少于两个周期为偏紧；无法支付时禁止执行。
- 所有整数运算使用溢出检查、大整数中间值或饱和边界，极端存档不会回绕为错误收益。

### 执行与低耦合

- `StoreInvestmentAdvisor` 只读取不可变经营、成长和员工快照并生成候选。
- `StoreInvestmentService` 在点击时重新生成组合，避免使用已经过期的价格、前置条件或候选池。
- 成功执行只转发给既有 `UpgradeStore` 或 `Employees.Hire` 命令；现金扣除、升级限制、招聘费用和员工创建仍由原模块唯一负责。
- WPF 的投资卡只格式化 Application 返回的数据并转发候选 ID，不持有任何回报公式。

### 投资后对照与存档

- 每家店只保存最近一笔投资及其最近完整日结基线。
- 下一份更晚的完整日结会比较净利润、成交数和流失数；缺少投资前完整日结时明确显示无法建立基线。
- `GameSaveData` 在 schema v6 末尾增加可空 `InvestmentTracking` 字段；旧 v1～v6 存档缺少该字段时按“无投资记录”恢复，不升级 schema。
- 员工投资与店铺成长投资共同计入首次投资新手目标。

## 验收结果

- 新增阶段级闭环覆盖：经营一天获得候选、至少三类可执行投资、执行货架投资、保存恢复、再挂机一天、产生实际日结对照。
- 管理窗口仍只有经营概览、经营策略、投资决策三个入口；招聘与店铺成长不再作为两个独立维护面。
- 固定现实 `1x`、在线/离线同一 `BusinessSimulation` Tick、24 帧人物表现和 schema v6 均保持不变。
- `dotnet test HajimaoDesktopShop.slnx -c Release --no-restore`：549/549 通过。
- `dotnet build HajimaoDesktopShop.slnx -c Release --no-restore`：0 警告、0 错误。
- 本阶段全部 C# 变更通过定向 `dotnet format --verify-no-changes`；人物图集工具 Python 测试 4/4 通过；11 个项目的 NuGet 直接及传递依赖均无已知漏洞。
- Windows 单文件便携 ZIP、MSI、SHA-256、发布清单及真实启动冒烟在合并发布门禁中再次验证。

## 已知边界与下一步

- 估算刻意保守，只衡量当前模型能解释且已经观察到的直接改善；它不是未来收益保证，也暂不模拟多项投资之间的长期复合效应。
- 投资前后对照显示相关变化，不宣称单个投资是变化的唯一因果；天气、策略和共享客流仍可能共同影响结果。
- 0.1.19 将建立首次接触、跨日经营、多次回归、多店扩张和完整街区五段长期成长标尺，调整开局现金、工资、采购、经验、开店和升级成本，并提供亏损诊断与现金保护。30～60 分钟只观察早期理解度，不代表游戏寿命。
- 0.1.20 将同时进行首次接触盲测、跨真实日回访和 1/7/30 经营日自动情景，决定是否达到“挂机增量 Demo 1”。
