# 0.1.2 挂机与完整多店存档阶段总结

日期：2026-08-03  
状态：完成

## 本阶段结果

- 完整 v3 存档覆盖玩家经验、共享资金、所有已开店铺、商品价格/库存、逐店财务、全部员工及精确工资状态。
- 运行时存档覆盖结账队列顺序、进行中的结账及剩余分钟、整洁度、服务、工资失败次数、日结起点与队列累计。
- 64 位确定性随机状态与业务状态一起保存，恢复后的下一个随机决策保持一致。
- SQLite v1/v2 存档逐级事务迁移至 v3；旧单店数据和现场字段继续保留。
- `BusinessSession` 统一新会话、完整恢复、旧单店升级和首店兼容投影。
- 关闭期间最多补算 28,800 个现实整秒；每批最多 10,000 秒，但内部仍逐 Tick 走在线规则。
- 时间倒退补算 0 秒并返回 `ClockMovedBackward`；小数秒截断，超出上限明确标记。

## 模块边界

- Domain 只提供经过不变量验证的员工、共享钱包和店铺财务恢复入口。
- Application 定义存档 DTO、会话组合、随机状态接口和离线政策，不引用 SQLite、WPF 或 Skia。
- Infrastructure 实现可恢复随机源和 SQLite 迁移，不持有经营规则。
- Desktop/Rendering 保持 0.2 兼容外壳，正式管理 UI 仍后置。

## 已知边界

- 当前 WPF 组合根仍使用原型单店 `ShopSimulation`；完整 `BusinessSession` 已具备 SQLite 契约，但正式 UI/组合根切换随 0.7 管理前端完成。
- 旧 v1/v2 存档完整保留原字段；升级到多店运行时时，将首店业务状态映射到配置的起始店，旧顾客/补货现场继续留在兼容字段中。
- 离线结算会真实消耗库存和工资；0.4 自动补货完成前，长时间离线可能因缺货或资金不足降低收益。
