# Hajimao DesktopShop 0.1.21 Long-Term Readiness

## Scope

0.1.21 keeps the project at **Playable Demo Candidate 1**. It extends the existing Candidate evidence to one-year deterministic operating scenarios and adds a privacy-bounded feedback ZIP workflow for blind tests. It does not add a new gameplay system, content set, save schema, speed mode, reward loop, or Demo 1 claim.

The release-facing delivery remains the public portable ZIP. Testers should right-click the notification area icon, choose `生成测试反馈包`, and return the desktop ZIP with observation notes. The ZIP contains an aggregate snapshot and sanitized diagnostic event headers only; it omits the save database, raw logs, personal paths and machine paths.

## Feedback Export Evidence

The feedback export architecture separates responsibilities:

- Application maps `BusinessSimulationSnapshot` into a `PlaytestFeedbackReport` with version, schema, aggregate business/store values and sanitized event headers.
- Infrastructure reads only whitelisted structured log headers and writes `feedback.json` plus a README into a ZIP.
- Desktop tray and `App` orchestrate one snapshot capture, one sanitized log read and one archive write.

Privacy and stability review caught two real defects before this report:

- Active log files could be exclusively held while the export reader opened them. The reader now uses `FileShare.ReadWrite | FileShare.Delete` and skips only the inaccessible file.
- Same-second concurrent ZIP creation could collide after the existence check. The writer now uses bounded unique suffix retries around atomic `File.Move`.

The report deliberately excludes save DB payloads, raw log lines, stack traces, user names, data-directory paths, machine paths, customer IDs, employee IDs, candidate details, product details and store names.

## Candidate Boundary

0.1.21 preserves the fixed real `1x` economy, 24-frame character timeline, online/offline same `Tick`, schema v6 and existing playable surface. It is long-term readiness and feedback plumbing for the Candidate, not Demo 1.

The blind-test gate remains `0/3` unless repository evidence is added later. Three real unfamiliar-player observations, each with a returned sanitized ZIP and notes, are still required before any release text may say Playable Demo 1.
