# Hajimao DesktopShop 0.1.23 店铺类型底层

## 本阶段结果

0.1.23 完成“先打底层、后做选择界面”的店铺组合内核：

- `ShopId` 只代表一间店铺实例，`StoreBrandId` 代表品牌身份，`StoreFormatId` 代表可复用经营算法；三者不再混为一个固定关卡。
- 开店移除等级门槛。等级仍用于逐步解锁商品，扩张由玩家选择、开店成本与经营储备决定。
- 四种经营形态把利润和风险差异落到需求敏感度、时段、容量、价格容忍、队列与商品偏好，而不是直接乘净利润。
- 每次扩张可生成三份品牌提案并覆盖至少两种经营形态；执行会动态创建店铺、同步模拟运行时并把投资追踪绑定到新实例。
- 街区不设五店上限，实际店铺数量决定宽度、层级和访客机会；1/2/5/6/20/100 店均有覆盖。
- schema v7 保存动态店铺的名称、品牌、形态与街道顺序；旧 v6 固定店铺迁移为 7-Eleven、FamilyMart、Lawson 兼容身份，v1～v5 继续逐级迁移。

## 内容资源

- 品牌：24 个知名店铺文字名称，四种形态各至少 5 个。
- 商品：40 种，覆盖常温、冷藏、冷冻，不同进价、售价、毛利、容量和等级。
- 单店精选货盘：最多 12 种，按品牌稳定选择；重启结果一致，不同品牌可形成不同货盘。
- 真实名称当前均标记为 `review-required`；像素门面继续使用原创通用样式，不复制 Logo、包装或标志性店装。

## 数值自检

首次将 40 种商品全部注册到每家店时，完整 Release 门禁发现高周转路线在第 25 日开第二店后，自动补货几乎耗尽全部现金并产生工资失败。没有降低门禁，而是修正资源模型：丰富的是全局目录，单店只承担有限货架。

修正后，原先失败的 30 日四项场景、90 日三项场景和 demo 扩张链路均重新通过；开店等待逻辑也明确避开严重现金压力。

## 当前边界与下一步

- 本阶段完成算法、动态执行、存档和首批丰富数据，尚未把三品牌提案展开成最终玩家选择界面。
- 新玩家仍暂用 7-Eleven 作为兼容起始店；下一阶段增加四选一开局，并让管理页的“扩张街区”展开三张简洁品牌卡。
