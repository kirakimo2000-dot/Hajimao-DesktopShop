# Hajimao DesktopShop 0.1.26 首店选择

## 本阶段完成

- 新玩家首次启动会看到三种首店：社区便利、平价量贩、精品食品。界面每项只回答“靠什么赚钱、最怕什么、适合怎样经营”，不显示千分比、公式或新增日常操作。
- 三项并非皮肤选择。所选品牌与经营形态会进入真实 `ShopDefinition`，影响客流与价格/服务/排队/整洁敏感度、时段曲线、库存容量、商品偏好以及默认经营策略。
- 首店继续从一家开始、免开店费并保留 ¥1,200.00 启动资金；同一随机种子会在对应经营形态内稳定选出同一品牌。
- 选择结果沿用 schema v7 的品牌、经营形态、店名和街道序号字段保存。已有存档启动时完全绕过选择窗口，恢复原有首店与经营状态。
- 玩家在选择前关闭窗口时，应用直接退出；此时尚未创建经营会话，不会建立或覆盖新存档。

## 结构与低耦合

- Application 层的 `StoreOpeningProposalService` 只负责三种经济原型与确定性品牌候选，不依赖 WPF。
- Desktop 的 `StarterStoreChoiceViewModel` 只把后台差异翻译为简短自然语言；选择窗口只绑定数据和关闭对话框，不包含经济算法。
- `StarterStoreStartupCoordinator` 隔离“新档选择 / 旧档旁路 / 取消退出”，`DesktopBusinessSessionFactory` 只负责校验候选并建立实际会话。
- 稳定的首店实例 ID 保持不变，员工归属、采购、模拟与旧存档迁移无需跟随 UI 选择重写。

## 保持不变的玩法边界

- 只有程序运行中的真实 Tick 产生收益；没有倍速、暂停、离线收益或关闭期间追赶。
- 玩家等级继续解锁商品，不再用于解锁店铺；后续开店仍从三项提案中选择，并由共享资金承担风险。
- 首次选择没有增加补货、排班、事件领取或逐商品维护；这些规则继续在后台自动执行。
- 桌面街区仍永久置顶、靠近任务栏自动吸附并保持用户拖动的 X 轴；经营窗口不永久置顶。

## 验证证据

- 按 RED → GREEN 覆盖：三原型提案与启动资金、负资金拒绝、所选品牌/形态进入真实模拟、非法资源拒绝、选择身份存档恢复、旧档不调用选择器、取消不继续、选择只完成一次、窗口三卡绑定与无任务栏入口。
- 冻结后的统一 Release 入口完整通过 690/690：Domain 102、Application 246、Infrastructure 33、Rendering 110、Desktop 187、Release 12；Desktop 套件包含年度长期成长场景。
- 验证时发现 .NET 10.0.101 的解决方案级 `dotnet test` 在本机只执行 Application 与 Desktop 两个项目。新增 `scripts/test-all.ps1` 显式枚举六个测试项目，发布脚本与 GitHub Windows CI 现在复用同一入口，避免把部分测试误报成全套。
- 本地 Release 构建 0 警告、0 错误；GitHub Windows CI 作为第二道完整门禁，结果在 PR 合并前确认。
