# Hajimao DesktopShop 0.1.27 开局闭环加固

## 本阶段完成

- SQLite 读取不存在的数据库时直接返回空结果，只有确认首店并开始自动保存后才创建目录、数据库和 schema。
- 经营形态配置中的推荐定价与备货策略进入真实开店流程：便利店均衡经营、量贩店低价走量并充足备货、精品店高毛利并精简库存。
- 新手第一步从“再次选择策略”调整为“观察第一份日结”，首店选择负责确定初始投资方向，后续引导再进入投资与回报。
- 发布冒烟脚本只操作自己启动的隔离进程，通过 Windows UI Automation 选择首店，并以 `application.started` 作为经营会话已建立的门禁。

## 结构与兼容性

- 存档 schema 仍为 v7；已有数据库照常逐级迁移和恢复，旧存档不会重新选择首店。
- 推荐策略由 Application 层消费 `StoreFormatDefinition`，WPF 不包含定价、库存或收益算法。
- 经营形态差异仍通过配置扩展，店铺创建只调用统一策略规划器，没有新增店铺类型分支或 UI 专用状态。

## 验证证据

- SQLite 与推荐策略回归测试先分别失败于“数据库被创建”和“实际策略为 Balanced”，实现后聚焦测试通过。
- 新手流程、下一步投影、三种首店推荐策略和发布脚本合同均有自动化覆盖。
- 三条 365 日路线均保持现金非负、无工资支付失败；精品店前 90 日偏向店内投资，之后仍保留扩张路线并在年度内达到六店。
- 最终冻结后统一 Release 测试入口通过 696/696：Domain 102、Application 246、Infrastructure 33、Rendering 110、Desktop 193、Release 12。

## 已知边界与下一步

1. 发布脚本的真实便携包/MSI 生命周期仍应由 GitHub Windows 发布门禁执行，本阶段不在用户桌面启动图形程序。
2. 下一阶段继续收束具体店铺页，只保留本店表现、主要原因和下一项投资。
3. 再补短期事件历史与投资前后对比，然后进行陌生玩家首轮测试。
