# v0.1.31 首局体验与挂机正反馈

日期：2026-08-14

## 问题基线

真实体验反馈确认 v0.1.30 的开发结论高估了玩家体验：桌面常态几乎不呈现挂机收益，首个任务要求等待一份完整日结，经营页的下一步又把玩家送回当前概览。自动测试证明了系统存在，却没有证明玩家知道要做什么、为什么保持游戏运行。

本阶段不再用资源数量或长期 runner 代替体验证据，直接处理三个问题：视觉引导差、首局无明确动作、挂机正反馈不可见。

## 完成内容

- 新增 Desktop-only `IdleSessionFeedbackViewModel`，以启动快照为基线，持续投影本次运行净收益、成交增量、经营日进度、结算倒计时和当前目标。
- 248×180 单店街区顶部显示现金与本次收益，底部显示成交、结算倒计时和唯一目标；多店横向增长、永久置顶、拖动吸附、X 轴保持和鼠标穿透不变。
- 经营概览先显示“这次打开游戏的成果”，页头提供明确的“回到挂机街区”主动作；鼠标穿透降为辅助按钮。
- 新手第一步改为选择真实定价/备货方向，不再执行无意义的“看概览”；策略按钮显示客流、单利、缺货与现金占用取舍，并明确标记当前选择。
- 首店选择从三张同质灰色文字卡改为带像素店面轮廓、经营色、回报类型和风险定位的投资选择。
- 设计遵守有限像素色板、单一主动作、可见成功反馈、12 像素最小正文、44 像素命中目标和系统减少动态效果约束。

## 架构边界

- 未修改 Domain、Application、Infrastructure 或 Rendering 的经营规则。
- 本次收益是既有累计净利润相对本次程序启动时的差额，不伪造奖励，也不把采购或投资支出包装成收入。
- 成交和日结进度只读取现有不可变快照；固定现实 1x、仅运行时收益、关闭冻结、schema v7 和自动保存保持不变。

- 首局、窗口、策略与反馈聚焦测试 51/51 通过；最后的窗口/策略复核 33/33 通过。
- 最终变更层门禁通过：Desktop 213/213、Release 12/12。Domain 102、Application 246、Infrastructure 33、Rendering 110 沿用 v0.1.30 已通过证据，因为本阶段未修改这些项目；统一候选总数为 716。
- 离屏检查覆盖 960×620 首店页、248×180 街区，以及 1180×720 经营概览/策略/投资三页；Skia 场景本体仍由 Rendering 测试验证。
- 本地便携 ZIP 只含 `Hajimao DesktopShop.exe`，文件版本 `0.1.31.0`，ZIP 为 84,042,570 字节，SHA-256 为 `77e8d33111241ea69b0451163b21446c62e092149ed6b93d3372462bc25381cf`。

## 已知边界

- 自动快照仍不能回答玩家是否愿意第二次打开游戏；v0.1.31 只能作为新的真实体验候选，不自动晋级 Playable Demo 1。
- 当前正反馈以数值、目标和场景营业为主，尚未增加成交飘字、投资完成动画或店面升级前后对照。
- 首份完整日结仍需要 24 个现实分钟；现在进度与理由可见，但节奏是否合理必须由真人挂机观察确认。
- 为避免操作用户桌面，本轮没有自动启动便携 EXE；运行验证使用 WPF 离屏窗口、绑定测试和现有业务会话测试，最终实际体验由用户手动启动候选包确认。

## 下一步

- 先让真实玩家体验本地候选，观察是否在不看说明的情况下完成首店选择、选择策略、返回街区并理解本次收益。
- 若仍缺乏期待感，下一轮优先加入由真实成交触发的短促场景反馈和可见的投资前后变化，不新增经营页面或后台系统。
- 只有重复反馈证明信息仍不清楚时，才继续调整文案和布局。
