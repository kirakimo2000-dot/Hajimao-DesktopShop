# v0.1.4 阶段总结：员工经营

## 本阶段结果

- 新增独立的员工经营模块，候选、招聘、调店、排班和培训不依赖 WPF 或 SQLite。
- 候选池由独立、可恢复的确定性状态生成，候选 ID 单调递增，不改变顾客模拟的随机序列。
- 招聘费为基础小时工资的 40 倍；培训为五级，每次按下一等级与小时工资计费；资金不足时命令不产生半笔状态。
- 正常班次最长 480 分钟，支持日班与跨午夜；旧存档员工使用显式兼容常驻班次，避免升级后店铺突然停摆。
- 体力、满意度和培训以纯整数倍率组成有效效率。成功付薪的排班员工消耗体力并贡献岗位效率，非排班员工恢复体力。
- 收银、清洁和服务统一使用有效效率；在线与离线挂机继续运行同一固定分钟 Tick，没有暂停或倍速功能。
- schema v5 保存候选池、候选随机状态、员工条件、培训、店铺分配和班次，并逐级迁移 v1～v4。

## 模块边界

- `Domain.Employees`：员工工资、培训、体力、满意度和有效效率不变量。
- `Application.Business.Employees`：候选池、招聘/培训命令、店铺分配、排班与不可变快照。
- `Application.Business.Simulation`：只解析当前分钟可工作员工并提交工资/工作结果。
- `Infrastructure.Persistence`：只负责 schema 迁移和 JSON/SQLite 持久化，不持有玩法公式。
- WPF 暂不增加正式员工页，避免前端先于玩法定型。

## 验证证据

- Release 全量测试：162/162 通过。
- Release 构建：0 警告、0 错误。
- NuGet 漏洞审计：10 个项目的直接与传递依赖无已知漏洞。
- 覆盖正常/跨午夜排班、8 小时上限、招聘与培训原子性、体力/满意度变化、资金不足停工、在线/离线一致性、候选与员工完整恢复及 v4→v5 迁移。

## 当前差距

- 正式员工管理页面尚未制作；当前能力通过 Application 命令与快照提供。
- 候选人特质、岗位熟练度、请假和解雇补偿尚未进入 0.1.4 范围。
- 旧存档兼容常驻班次保留旧经营节奏；玩家在未来管理页面修改班次后即转为正常 480 分钟上限。

## 下一步：v0.1.5 单店成长

1. 建立店铺装修、设施等级和扩建槽位的领域模型。
2. 加入促销、客群与短期经营事件，同时保持固定现实时间和确定性存档。
3. 让单店成长与等级、商品、员工配置形成可解释的中期目标。
4. 继续只提供玩法命令、快照和存档；正式管理前端留到 v0.1.6。
