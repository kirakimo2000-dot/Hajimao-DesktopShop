# v0.1.5 阶段总结：单店成长

## 本阶段结果

- 每家已开店铺独立拥有扩建、货架和装修等级；多店继续共享业务资金，但费用计入发生店铺的经营成本。
- 扩建提高面积、货架位、排队舒适容量和客流吸引力；货架提高所有现有及未来商品的库存容量；装修提高客流吸引力。
- 三类升级使用固定平方成本和明确满级/前置约束。校验、共享资金扣款、容量更新、费用累计和账本写入原子完成。
- 本地传单、折扣券和节庆活动按真实分钟运行，同店同一时刻只允许一个活动；折扣券和节庆活动需要对应成长等级。
- 需求快照分别解释成长吸引力和促销修正，扩建的排队舒适容量只削减队列惩罚。
- 成长及促销费用纳入逐店净利润与日结；在线与离线使用同一固定 1x Tick，活动在当前分钟生效后于 Tick 末扣时。
- schema v6 保存逐店成长等级、运营成本、活动种类和剩余分钟；v5 迁移默认零级成长、无活动并保留既有经营状态。

## 模块边界

- `Domain.Shops`：成长等级、派生容量、升级约束、库存扩容和经营费用不变量。
- `Application.Business.StoreGrowth`：升级/促销命令、活动生命周期和不可变成长快照。
- `Application.Business.Simulation`：只读取成长快照，将修正接入需求、队列和日结。
- `Infrastructure.Persistence`：只迁移与保存 schema v6 数据，不持有成本或需求公式。
- WPF 暂不增加正式成长页面，避免界面先于完整玩法底层定型。

## 验证证据

- Release 全量测试：180/180 通过。
- Release 构建：0 警告、0 错误。
- NuGet 漏洞审计：10 个项目的直接与传递依赖无已知漏洞。
- 覆盖升级费用/前置/资金原子性、现有与未来商品容量、促销互斥与倒计时、需求分解、队列舒适容量、日结经营成本、在线/离线一致性、完整恢复及 v5→v6 迁移。

## 当前差距

- 当前 WPF 仍是原型单店兼容界面，尚未展示多店、采购、员工和成长命令；底层快照已准备完毕。
- 平衡参数为首轮确定值，后续需通过长期自动模拟和正式管理界面试玩再调整。
- “相邻店铺扩建”当前表现为单店扩建等级和面积单元，正式像素场景中的空间变化留到 0.1.7。

## 下一步：v0.1.6 管理前端

1. 建立正式管理导航，把商品、采购、员工、店铺成长和财务快照接入独立页面。
2. 为升级、促销、排班与自动补货提供状态清晰的命令入口和失败反馈。
3. 保持桌面小店与管理窗不进入普通任务栏，继续通过通知区域图标管理显示与退出。
4. 不加入暂停或倍速；挂机价值继续来自自动化、人员配置、容量成长和真实离线结算。
