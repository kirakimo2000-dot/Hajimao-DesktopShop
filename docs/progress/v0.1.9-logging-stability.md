## 本阶段结果

1. 修复正式桌面启动遗漏离线结算的问题。恢复 schema v6 存档后，应用会按保存时间与当前 UTC 的整秒差调用同一 `BusinessSimulation.AdvanceRealSeconds` 管线；默认上限 28,800 秒、批次 10,000 秒，不存在倍速、跳时或另一套挂机公式。
2. 新局返回明确的启动结果且不执行离线结算；恢复结果公开请求秒数、实际秒数、是否封顶、时钟异常及结算前后经营总计。
3. 离线推进完成后立即写入新的 schema v6 检查点，避免启动后第一个五秒自动存档前异常退出导致下次重复补算。系统时间回退时不推进、不覆盖为更早的结算检查点。
4. 建立 `Application.Diagnostics` 结构化事件端口。事件只包含稳定名称、等级、消息、只读字符串属性和可选异常；没有时间戳、路径、WPF 或 Serilog 依赖。
5. `Infrastructure.Logging` 使用 Serilog 4.4.0 与 Serilog.Sinks.File 7.0.0 写入 `%LocalAppData%/HajimaoDesktopShop/logs/hajimao-*.log`。若设置 `HAJIMAO_DATA_DIRECTORY`，数据库与日志会一起进入隔离目录。
6. 日志按天和 5 MiB 文件大小双重滚动，最多保留 14 个文件并即时刷盘。只记录启动/恢复、离线结算或时钟异常、模拟线程故障、自动/最终存档失败和退出，不记录每个 Tick 或每次成功自动存档。
7. 日志创建或写入失败会降级为无操作 sink，不阻止模拟、保存或退出；后台循环的非取消异常只报告一次并停止，正常取消不记录错误。
8. 新增 `BusinessSimulationAuditService`，只调用公开批量推进和不可变快照。报告按店铺 ID 稳定排序，覆盖现金/经验以及逐店访客、购买接受、完成销售、流失、工资失败、营收、采购、毛利、工资、运营费、净利、结束队列、整洁度和库存。

## 审阅修正

- 日志目录不可创建不能成为游戏启动的单点故障：启动组合改为捕获日志初始化异常并降级到空 sink。
- 启动失败不能记录成正常退出：只有完整启动成功才写 `application.stopped`。
- 离线结算不能等待五秒自动存档才持久化：实际推进后立即捕获并保存 schema v6 检查点。
- Domain、ViewModel 和 WPF 中均无 Serilog 引用；Desktop 不包含经营差值公式，审计服务不包含测试专用状态修改入口。
