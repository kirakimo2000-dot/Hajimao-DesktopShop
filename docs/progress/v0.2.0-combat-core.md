# Hajimao DesktopShop 0.2.0 阶段报告

日期：2026-08-15

## 阶段结论

0.2.0 已完成“小重做”：主动玩法不再是补货卖货，而是桌面挂机战斗经营。毛毛自动投掷装备商品招待顾客；成功招待产生现金与随机商品掉落。只有程序运行时推进，没有游戏内时间、离线收益或倍速。

## 已完成

- 一家店开局，首店三种风险收益选择；后续每次扩张显示三家候选店。
- 便利、折扣、精品三类战斗参数实际影响客流容量、顾客需求、移动速度与收益。
- 账号共享商品图鉴、重复掉落精通、逐店装备和自动槽位成长。
- 24 种商品、12 类顾客、4 个现实本地时段池、11 种事件修正全部通过引用与掉落可达性校验。
- 战斗状态、收益、掉落、图鉴、装备和多店状态进入 schema v8 存档；恢复不会补算关闭时间。
- 店内只绘制背景、毛毛、顾客和投掷物；无货架交互。顾客显示需求条，命中、金币和掉落有即时反馈。
- 骨骼、皮肤、动作、角色定义分离；10 类动作严格为 24 个逻辑帧，移动和投掷物使用表现帧插值。
- 街区页不显示任务，长度随店铺数量增长；窗口拖动、任务栏吸附、始终置顶、鼠标穿透和页面位置约束保留。
- 管理页收束为挂机成果、战斗策略、新增店铺；旧定价、补货、货架、员工和报告按钮退出主动界面。
- 项目根目录保留可直接启动的 0.2.0 单文件 EXE，ZIP 也只有一个 EXE。

## 底层结构

- Domain：纯确定性目标选择、冷却、投掷物、命中、招待、逃离、图鉴和装备规则。
- Application：现实顾客池、运行事件、掉落、精通倍率、收益、多店参数、扩张与不可变快照。
- Rendering：只消费快照与事件，负责背景、骨骼、移动插值和战斗反馈，不计算伤害或掉落。
- Desktop：只发出装备与开店命令，展示少量可解释结果。
- Infrastructure：严格加载 JSON 内容并保存 SQLite schema v8。

## 当前局限

- 店铺内饰仍是轻量占位图，顾客暂时复用通用骨骼皮肤并通过颜色区分。
- 商品与顾客数量足以验证完整循环，但下一阶段仍需基于真实测试扩充内容。
- 旧零售类型仍有一部分作为旧存档兼容层保留，不会被 0.2 主动界面或运行循环调用。
- 自动测试证明规则与资源一致，不能替代首次上手是否清楚、节奏是否有正反馈的真人体验。
