# Hajimao DesktopShop 0.2.3 核心稳定性阶段

日期：2026-08-17

## 本阶段目标

在不增加新玩法系统的前提下，修复 0.2 战斗挂机闭环中会导致崩溃、停摆、收益反馈不可见、动画断裂和常驻性能浪费的问题。

## 已完成

- 战斗 Tick、快照、装备和存档捕获统一使用同一状态锁，后台结算与 WPF 展示不再并发读取半更新状态。
- 恢复存档时清除当前内容目录不支持的顾客与投掷物，同时清理已失效的投掷目标。
- 商品 `BonusDrop` 效果接入真实掉落结算；普通掉落未触发时可进行一次装备加成判定。
- 最近招待与掉落提示保持 3 秒；没有新事件后再回落到攻击中或等待顾客状态。
- 场景保持 24 FPS，管理集合改为每秒刷新一次；直接选择店铺、装备和投资仍立即完整刷新。
- 毛毛的 24 帧投掷动作分为蓄力、投掷、收势；顾客成功招待与逃离均保留一段可见退场动画。
- 单次后台结算异常不会永久停止挂机循环；应用退出时最终存档优先于单实例租约释放。
- 经营窗口可缩至 720×500，并在加载时约束到当前工作区，右侧内容继续使用纵向滚动。

## 已知缺口

- 按用户要求，本阶段未自动启动或操作桌面窗口，因此尚未替代真实用户完成 15～30 分钟可见挂机验收。
- 顾客退场事件没有保存最后命中坐标，当前成功退场动画使用稳定的店内预设位置；后续可在事件快照中补充表现坐标。
- 本阶段只修复 UI 刷新频率与小屏适配，没有重新设计整体视觉层级。

## 下一步

1. 用真实便携构建进行 15～30 分钟人工挂机测试，记录 CPU、内存、掉落可读性和动画节奏。
2. 根据真实体验调整首轮顾客刷新、战斗伤害与商品掉落节奏，不新增额外操作系统。
3. 统一桌面街区和经营页的关键正反馈视觉，再进入 0.2.4。
