# Hajimao DesktopShop 0.2.8 代码审查优化阶段

日期：2026-08-18

## 本阶段目标

修复 0.2.7 审查发现的四项根因：致命退场坐标不一致、人物热路径原生分配、异步资源异常逃逸，以及配置验证与渲染硬编码契约脱节。

## 已完成

- 退场编舞读取对应顾客最后一条 `ProductHitEvent.TargetPositionPermille`，人物和致命掉血反馈从同一命中坐标生成。
- `SkeletalCharacterRenderer` 只接受可复用 `SKImage`；街道和店铺场景各创建一次图片并在销毁时释放。
- `HumanCharacterRenderer` 复用场景现有 `SKPaint` 绘制配饰，不再逐人物逐帧创建画笔。
- 三个人物场景控件捕获非取消加载异常，写入 `Trace` 并显示深红故障画布，避免 `async void` 异常终止游戏。
- JSON 人物目录强制包含唯一 `humanoid-v1`，以及 `head`、`torso`、`hand-right` 必要骨骼。

## 已知缺口

- 骨骼绘制仍会按 ZIndex 排序；它只产生少量托管临时对象，当前没有测得卡顿，因此本轮不增加缓存结构。
- 资源加载失败使用故障色和系统 Trace，不新增复杂错误页面；正式玩家提示可与后续 HUD 优化一起设计。

## 下一步

1. 精简店铺 HUD，突出当前威胁、挂机收益、招待结果和掉落。
2. 增强连续命中、招待成功和稀有掉落的正反馈层级。
3. 在共用骨骼规范下增加独立头部、发型和服装部件。
