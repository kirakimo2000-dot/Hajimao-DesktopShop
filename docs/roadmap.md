# 正式版本迭代路线

正式版本从 `0.1.0` 开始。此前交付统一归档为原型历史。每个版本必须可构建、可验证，并同步更新 `CHANGELOG.md`、`docs/progress/`、下一阶段计划和工作区清理记录。

正式发布前的当前路线统一使用 `0.1.x` 补丁版本递进，避免把单个底层模块误标为新的次版本；只有成熟发布时才进入 `1.0.0`。

开发顺序遵循：`玩法底层 → 模拟与经济 → 挂机与自动化 → 内容 → 前端/UI → 商业街 → 1.0`。

| 版本 | 阶段目标 | 可验证交付 |
| --- | --- | --- |
| 0.1.0 | 玩法底层 | 固定现实 1x；玩家等级；商品/店铺解锁；多店共享资金；商品毛利；员工效率/工时费；托盘常驻 |
| 0.1.1 | 多店模拟与经营深度 | 多店同时 Tick；价格/需求/服务/队列/整洁度；工资结算；日结与净利润 |

## 当前 0.1.16 边界

- 正式 WPF 已运行 `BusinessSession`，管理页只通过 Application 命令和不可变快照操作经营状态。
- 七区导航覆盖店铺、商品、进货、员工、成长、财务与商业街预告；同一时刻只展开一个内容面。
- 桌面街区从单店 248×180 起按已开店数增长，具体店铺仍为 420×280，管理窗为 1180×720；窗口不创建普通任务栏按钮。
- 游戏固定现实 1x，不存在暂停、倍速或速度选择；挂机收益只能通过经营、自动化与成长改善。
- schema v6 必须逐级迁移 v1～v5；不得丢失旧资金、库存、采购、员工或运行时状态。
- 正式像素图集、全人物 24 帧时间轴、8 个去重关键姿势和移动路径、三类货架、十种商品、定制芯片音效和品牌托盘图标已经交付。
- 表现层只消费不可变经营快照；固定现实 1x、离线同管线和 schema v6 保持不变。
- 商业街按 Lv.1/Lv.3/Lv.5/Lv.10 逐段解锁，所有已开店铺共享同一客流池；多店每分钟最多接收一名由吸引力加权分配的街道访客。
- 晴朗、多云、雨天和大风由经营分钟确定性切换；天气影响客流，路人/车辆只作为快照派生的有预算表现，不进入存档。
- 管理窗商业街页面显示多店、客流份额和环境场景，底部状态栏可收起；固定现实 1x、schema v6 和离线同管线不变。
- 0.1.9 已完成教程、平衡/长时稳定、正式日志、多显示器矩阵、便携 ZIP、per-machine MSI 与 GitHub Windows 安装门禁。
- 0.1.10 已完成无限横向街区、店面点击导航、镜头和人物移动。
- 0.1.11 已完成顾客进店、寻找三类货架、拿货、排队、结账和离店的连续表现；路径是只读视觉投影，不改变经营结算与存档。
- 0.1.12 已完成货架/员工对象命中、详情投影及桌面/管理窗口统一导航；点击只读取快照，不推进经营时间或修改经济状态。
- 0.1.13 已完成货架快速进货/自动补货和员工培训/排班；动作复用既有 Application 命令，不推进经营时间。
- 0.1.14 已清除人物坏像素并把运行时图集压缩到 24 KiB 预算内；所有人物共用 24 帧表现契约。
- 0.1.15 已将收银、补货、清洁、导购、休息和待命统一为真实任务快照；在线/离线使用同一任务规划器，员工位置与详情只读消费当前任务。
- 0.1.16 将便携 ZIP 收敛为单个 `Hajimao DesktopShop.exe`；安装版继续使用独立多文件负载，经营与存档规则不变。
- 0.1.17 继续店铺经营身份：差异化店面、主题、商品组合与客群联动；近期版本继续以游戏内容为主。
- 签名、真实硬件矩阵及其他兼容/合规工作统一延后到正式发布准备阶段，不占用近期玩法迭代。

## 每阶段出口条件

1. 新行为有明确失败测试，并完成 RED → GREEN → REFACTOR。
2. 完整 solution Release 构建无警告/错误，所有测试通过。
3. NuGet 漏洞检查无已知漏洞。
4. Changelog 与版本阶段报告包含完成项、证据、遗留和下一步。
5. 只保留源文件、必要配置、确认资产和正式发布物。
