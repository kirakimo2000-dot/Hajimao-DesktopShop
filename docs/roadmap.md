# 正式版本迭代路线

正式版本从 `0.1.0` 开始。此前交付统一归档为原型历史。每个版本必须可构建、可验证，并同步更新 `CHANGELOG.md`、`docs/progress/`、下一阶段计划和工作区清理记录。

正式发布前的当前路线统一使用 `0.1.x` 补丁版本递进，避免把单个底层模块误标为新的次版本；只有成熟发布时才进入 `1.0.0`。

0.1.16 后停止横向堆叠系统，开发顺序改为：`收敛决策面 → 建立投资回报 → 建立长期成长标尺 → 挂机增量 Demo 1 → 再扩充内容`。30～60 分钟只用于观察早期理解度，不再作为产品寿命或“完整体验”目标。完整产品计划见 `docs/design/playable-demo-plan.md`。

产品北极星：玩家是投资经营者，不是执行逐次采购、排班和补货的店员。底层保持模块化，玩家界面只暴露少量高影响、可解释、有机会成本的决策。

## 当前 0.1.26 边界

- 正式 WPF 已运行 `BusinessSession`，管理页只通过 Application 命令和不可变快照操作经营状态。
- 玩家界面只保留经营概览、经营策略和投资决策；商品、采购、员工、成长、财务等内部模块继续通过 Application 命令协作。
- 桌面街区从单店 248×180 起按已开店数增长，具体店铺仍为 420×280，管理窗为 1180×720；窗口不创建普通任务栏按钮。
- 游戏固定单速且不显示 1x 状态文字；只有程序运行中的真实 Tick 产生挂机收益，关闭期间完全冻结。
- schema v7 必须逐级迁移 v1～v6；不得丢失旧资金、库存、采购、员工、店铺身份或运行时状态。
- 正式像素图集、全人物 24 帧时间轴、8 个去重关键姿势和移动路径、三类货架、十种商品和品牌托盘图标已经交付；音效系统已在 0.1.22 删除。
- 表现层只消费不可变经营快照；固定单速、运行时 Tick 和 schema v6 保持不变。
- 玩家等级只解锁商品；新增店铺由资金和三项品牌方案决定。街区长度随实际店数增长，不设生产上限。
- 晴朗、多云、雨天和大风由经营分钟确定性切换；天气影响客流，路人/车辆只作为快照派生的有预算表现，不进入存档。
- 管理窗右栏可滚动并只显示一个下一步；底部状态栏、固定 1x 文本和音效入口已经删除。
- 0.1.9 已完成教程、平衡/长时稳定、正式日志、多显示器矩阵、便携 ZIP、per-machine MSI 与 GitHub Windows 安装门禁。
- 0.1.10 已完成无限横向街区、店面点击导航、镜头和人物移动。
- 0.1.11 已完成顾客进店、寻找三类货架、拿货、排队、结账和离店的连续表现；路径是只读视觉投影，不改变经营结算与存档。
- 0.1.12 已完成货架/员工对象命中、详情投影及桌面/管理窗口统一导航；点击只读取快照，不推进经营时间或修改经济状态。
- 0.1.13 已完成货架快速进货/自动补货和员工培训/排班；动作复用既有 Application 命令，不推进经营时间。
- 0.1.14 已清除人物坏像素并把运行时图集压缩到 24 KiB 预算内；所有人物共用 24 帧表现契约。
- 0.1.15 已将收银、补货、清洁、导购、休息和待命统一为真实任务快照；在线/离线使用同一任务规划器，员工位置与详情只读消费当前任务。

- 0.1.17 已把七区导航收敛为三个投资者界面；全店定价/库存策略复用既有命令，日常补货和员工任务默认自动运行，场景对象只读解释经营状态。
- 0.1.18 已统一人员、货架、扩建和装修候选，按真实成本、可观察能力变化、保守日收益、回收期和现金压力呈现。

- 资本顾问从所有已开店铺派生最多三个方向：稳住弱店、提高回报、扩张街区；跨店执行仍唯一调用既有投资命令。
- 0.1.22 删除离线结算与回归简报；重新打开只恢复保存状态，不根据关闭时间补算收益。
- 店铺成长上限延长到扩建 20、货架 21、装修 21；平方成本曲线、升级前置、能力派生和 schema v6 存档结构保持不变。

- 0.1.21 未增加新玩法系统、商品内容或美术内容；它只延长既有成长深度、修正 runner 员工策略，并补齐盲测反馈回传链路。
- 正式生产入口验收已覆盖新档、投资比较、冻结式保存恢复、持续运行挂机、开第二店和弱店投资；这只是自动 Candidate 证据，不是陌生玩家盲测。
- 原定店铺主题、商品组合与客群联动延后到 Playable Demo 1 之后；核心循环未成立前不再用内容扩充掩盖可玩性问题。
- 签名、真实硬件矩阵及其他兼容/合规工作统一延后到正式发布准备阶段，不占用近期玩法迭代。

## 0.1.22 玩家操作预算

- 管理导航最多三个入口：经营概览、经营策略、投资决策。
- 玩家高频可见策略最多两个：全店定价定位、全店库存投入。
- 日常补货、采购渠道选择、员工任务、逐员排班和候选刷新默认自动运行。
- 场景对象点击只解释状态和因果，不提供重复维护按钮。
- 每个保留按钮必须改变未来现金流、经营能力或风险；不能满足这一条件的操作合并、隐藏或删除。
- 候选人按经营日自动刷新；招聘、扩建、货架、装修和开店由资本顾问压缩成最多三个跨店方向，不拆回独立维护区。
- 开设新店也使用同一投资比较面；等级未满足、资金不足和新店尚无日结证据都在同一张卡解释。
- 只显示一个长期目标和一个条件式恢复动作，不新增任务列表、恢复页、第二货币或每日登录奖励。
- 收益证据不足时允许玩家基于能力变化投资，但界面不得伪造回收期或承诺收益。

## Playable Demo 1 节点

0.1.22 仍是 Playable Demo Candidate。它已经自动证明持续运行挂机、多店扩张和一年经营后仍有下一层成长，并提供可回传的脱敏反馈 ZIP，但陌生玩家理解度不能由 runner 或 ZIP 代替。完成 `docs/playtests/v0.1.20-blind-test-protocol.md` 的三轮真实测试前，版本不晋级“挂机增量可玩 Demo 1”。第二家店不再被硬塞进 30～60 分钟，详细门禁见 `docs/design/playable-demo-plan.md`。

## 每阶段出口条件

1. 新行为有明确失败测试，并完成 RED → GREEN → REFACTOR。
2. 完整 solution Release 构建无警告/错误，所有测试通过。
3. NuGet 漏洞检查无已知漏洞。
4. Changelog 与版本阶段报告包含完成项、证据、遗留和下一步。
5. 只保留源文件、必要配置、确认资产和正式发布物。
