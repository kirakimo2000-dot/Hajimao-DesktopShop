# v0.2.0 Multi-Store Economy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a deterministic gameplay-only simulation where every open store processes demand, queues, employee work, wages, sales, cleanliness, and daily profit feedback on the same fixed-time clock.

**Architecture:** Domain owns the explainable integer demand formula and atomic wage/accounting rules. Application owns store runtime actors, deterministic tick order, immutable simulation snapshots, and day reports. Existing WPF and SQLite adapters remain unchanged; 0.3.0 will persist the new immutable contracts.

**Tech Stack:** .NET 10, C# 14, xUnit, existing Domain/Application projects.

- [x] **Step 3: Implement runtime actors**

`BusinessSimulation` owns one private `StoreRuntime` per open store and one `SimulationClock`. On each tick it:

1. synchronizes new stores in ordinal shop-ID order;
2. pays every assigned employee in employee-ID order;
3. lets paid cleaners restore cleanliness by `max(1, efficiency / 100)`;
4. lets a paid cashier reduce an active checkout whose duration came from `CalculateTaskMinutes(BaseCheckoutMinutes)`;
5. completes sales through `BusinessGameService.Sell`;
6. evaluates arrival and purchase scores through `DemandModel`;
7. enqueues accepted in-stock products and reduces cleanliness;
8. keeps all scores, queue lengths, payroll failures, visitors, sales, and abandoned purchases in immutable snapshots.

Default options are base arrival `3_000`, base purchase `9_000`, checkout `2` minutes, visitor dirt `12`, cleaner base recovery `10`, and initial cleanliness `1_000`. Validate every option and clamp cleanliness to `0..1_000`.

Run selected tests and all Application tests. Commit `feat: simulate deterministic multi-store operations`.
