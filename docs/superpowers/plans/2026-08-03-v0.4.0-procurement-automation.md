# Hajimao Market v0.4.0 Procurement and Automation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为多店经营增加三种采购渠道、在途配送、自动补货与缺货应急策略，并让在线、离线和存档使用同一套确定性规则。

**Architecture:** 采购规则位于 `Application.Business.Procurement`，不进入 WPF，也不让模拟器持有商品经济规则。`BusinessGameService` 组合采购模块并提供命令/不可变快照；`BusinessSimulation` 每个固定分钟只调用一次采购推进。`Domain.Shop` 负责“付款”和“收货”两个原子库存动作，schema v4 保存采购策略、订单序号与在途订单。

**Tech Stack:** .NET 10、C# 14、xUnit、SQLite JSON payload、现有 Domain/Application/Infrastructure 分层。

## Locked gameplay rules

| 渠道 | 成本倍率 | 最低采购量 | 配送分钟 | 定位 |
| --- | ---: | ---: | ---: | --- |
| `local-wholesale` | 1250‰ | 1 | 0 | 应急，立即到货 |
| `regional-distributor` | 1000‰ | 6 | 30 | 日常平衡 |
| `direct-manufacturer` | 850‰ | 24 | 120 | 低成本、大批量 |

- 渠道成本按“目录进价 × 倍率”逐件向上取整，避免折扣采购出现少计 1 分。
- 下单时一次性扣款并计入店铺采购成本；到货只改变库存，不重复扣款。
- 在途数量占用容量。因旧的即时补货占用空间时，已付款订单停在 `AwaitingSpace`，不会丢失。
- 自动补货以“现货 + 在途”判断；小于等于触发库存时补到目标库存，并按渠道起订量向上修正。
- 首选渠道下单失败且现货为 0 时，启用缺货应急策略的商品改用 `local-wholesale` 尝试补 1 件。
- 同一商店、商品只允许一条自动补货在途订单；手工订单仍需遵守总容量。
