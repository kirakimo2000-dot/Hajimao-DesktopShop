# Hajimao Market v0.1.4 Employee Operations Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 增加可招聘、可排班、可培训且具有体力与满意度的多店员工经营底层，并让工资、岗位效率、在线/离线 Tick 和存档保持一致。

**Architecture:** Domain 的 `Employee` 拥有员工长期状态和纯整数效率计算；Application 的 `EmployeeOperationsService` 拥有候选池、招聘、店铺分配和排班命令。`BusinessSimulation` 只查询当前分钟可工作的员工并提交工作结果，WPF 不直接持有员工规则。

**Tech Stack:** .NET 10、C# 14、xUnit、现有固定分钟模拟、SQLite JSON schema。

## Locked gameplay rules

- 体力、满意度均为 `0..1000`；新员工默认体力 `1000`、满意度 `700`。
- 培训等级为 `0..5`，每级基础效率增加 `50‰`；第 N 级培训费为 `基础小时工资 × (N + 1) × 8`。
- 工作每分钟消耗 2 点体力；未排班每分钟恢复 4 点。体力为 0 时不能工作。
- 有效效率 = 基础效率 × 培训倍率 × 体力倍率 × 满意度倍率，全程整数计算；体力倍率 `500..1000‰`，满意度倍率 `750..1050‰`。
- 每个排班使用店铺本地分钟 `0..1439`，开始时间含、结束时间不含；支持跨午夜班次，每日计划最多 480 分钟。
- 只有处于排班、体力大于 0 且工资支付成功的员工才产生岗位效率和工时费。
- 每完成 60 个工作分钟满意度减 1；每完成 120 个非工作分钟满意度加 1，上下限夹紧。
- 招聘费等于小时工资的 40 倍，从共享资金一次扣除；资金不足时不新增员工。
- 候选人由可恢复随机源和递增候选 ID 确定生成，避免重启刷新候选池套利。
