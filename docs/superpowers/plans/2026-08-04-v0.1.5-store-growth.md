# Hajimao Market v0.1.5 Store Growth Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建立“经营盈利 → 投资扩建/货架/装修/促销 → 改变容量与客流 → 获得更高长期经营上限”的完整单店增量成长底层。

**Architecture:** `Domain.Shops` 拥有店铺发展等级、升级约束、库存容量和经营费用不变量；`Application.Business.StoreGrowth` 负责升级/促销命令、活动生命周期与不可变快照。`BusinessSimulation` 只读取成长修正量并接入需求与队列公式；SQLite 仅保存 schema v6 状态，不持有玩法公式。

**Tech Stack:** .NET 10、C# 14、xUnit、现有固定分钟模拟、System.Text.Json、SQLite schema v6。

---

## Locked gameplay rules

- 每店独立拥有扩建、货架、装修等级；共享资金支付，但费用计入发生店铺的经营成本。
- 扩建等级 `0..4`：面积单元 `1 + level`，货架位 `3 + level × 2`，免受排队惩罚的人数 `level × 2`，客流吸引力 `level × 150` 基点。
- 货架等级 `0..5`：每级令所有商品容量倍率增加 `250‰`；新解锁商品也立即使用当前倍率。
- 装修等级 `0..5`：每级增加 `250` 客流基点。
- 下一等级费用：扩建 `60_000 × next²` 分、货架 `25_000 × next²` 分、装修 `30_000 × next²` 分。
- 货架和装修的下一等级不得超过 `扩建等级 + 1`；满级、前置不足或资金不足均不得产生半笔状态。
- 同一店铺同一时间只能有一个促销；活动当前分钟生效，在 Tick 末减少一分钟，降至 0 后停止。
- `local-flyers`：15,000 分、240 分钟、客流 +1,200 基点。
- `discount-coupons`：25,000 分、360 分钟、客流 +600、购买 +800 基点，要求装修 1。
- `festival-event`：50,000 分、480 分钟、客流 +1,600、购买 +600 基点，要求扩建 2 且装修 2。
- 成长与促销只改变经营瓶颈和需求，不改变固定现实 1x，也不直接线性发钱。
- v5 迁移后所有店铺使用零级发展和无促销；已有库存、订单、员工与资金保持不变。
