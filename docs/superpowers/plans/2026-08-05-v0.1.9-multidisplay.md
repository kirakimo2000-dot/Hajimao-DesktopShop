# v0.1.9 Multi-display Placement Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make desktop-shop restore and corner snapping correct across negative coordinates, monitor gaps, display removal, vertically arranged displays, and mixed DPI without changing saved schema or visual size.

**Architecture:** A pure Desktop geometry policy receives logical window bounds and an immutable list of logical display work areas. A separate Win32 adapter enumerates monitors and converts native work-area pixels using each monitor's effective DPI. `WindowInteractionService` remains the WPF facade and delegates all placement decisions to the pure policy. Desktop opts into PerMonitorV2 before UI creation through an application manifest.

**Tech Stack:** .NET 10, C# record structs, WPF, Win32 `EnumDisplayMonitors`/`GetMonitorInfoW`, Shcore `GetDpiForMonitor`, xUnit

`DesktopRect`, `DesktopPoint`, and `DesktopSize` validate finite coordinates and positive dimensions. The policy exposes:

```csharp
public static bool TryRestore(
    DesktopPoint saved,
    DesktopSize windowSize,
    IReadOnlyList<DesktopRect> workAreas,
    double minimumVisible,
    out DesktopPoint restored);

public static bool TrySnapToNearestCorner(
    DesktopRect currentWindow,
    IReadOnlyList<DesktopRect> workAreas,
    double margin,
    out DesktopPoint snapped);
```

Restore succeeds only when one work area intersects the candidate window by at least `minimumVisible` in both axes. Snap selects the work area with the smallest squared point-to-rectangle distance from the window center, chooses left/right and top/bottom from the area midpoint, and clamps the result inside the margin when the window is larger than available space.

- [x] **Step 3: Implement enumeration and delegate WPF placement**

`MonitorWorkAreaProvider.GetLogicalWorkAreas()` enumerates every monitor, reads `rcWork`, requests effective DPI, falls back to 96 only when DPI retrieval fails, converts with `ToLogicalRect`, and returns a read-only list sorted by logical left/top. Native structs and P/Invoke stay private to this adapter.

`WindowInteractionService.TryRestorePlacement` computes the actual/fallback WPF window size, obtains the work areas, calls `TryRestore`, and assigns `Left/Top` only on success. `SnapToNearestWorkAreaCorner` calls the policy; if enumeration returns no monitor, it leaves the window unchanged. Click-through behavior remains untouched.
