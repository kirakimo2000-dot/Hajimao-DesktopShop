# v0.1.17 Core Loop Slimming Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace Hajimao DesktopShop's seven maintenance-heavy management surfaces with a small investor loop built around store-level strategy, automatic operations, explainable economics, and low-frequency investment.

**Architecture:** Existing procurement, employee, growth, simulation, persistence, and rendering modules remain separate. New pure Application analysis and strategy planners translate a whole-store decision into existing price and auto-restock commands; Desktop consumes their immutable snapshots through three player-facing sections. No save schema change is required because applied prices, restock policies, employees, and upgrades already persist.

**Tech Stack:** .NET 10, C# 14, WPF, CommunityToolkit.Mvvm, xUnit, SQLite schema v6, SkiaSharp rendering.

---

## Non-negotiable design constraints

- Keep fixed real-time `1x`; add no pause, speed, click-income, or offline multiplier.
- Add no products, staff roles, store themes, customer types, animations, or visual asset files.
- Expose at most three management sections: `Overview`, `Strategy`, `Investment`.
- Remove player-facing per-product ordering, per-product auto-restock toggles, candidate refresh, training, store assignment, and individual shift buttons.
- Retain underlying commands until no application or migration path needs them; remove UI coupling first, then delete only proven-dead Desktop code.
- Use existing stored sale prices and `AutoRestockPolicy` records; do not introduce schema v7.
- Keep store, procurement, employees, growth, simulation, and Desktop in their established layers; do not create a catch-all manager.

## Plan self-review

- **Spec coverage:** The plan explicitly reduces operation count, automates routine work, retains modular internals, exposes ratios and bottlenecks, and reserves ROI projection for 0.1.18. It does not expand resources.
- **Scope boundary:** 0.1.17 makes the existing game operable with a small decision surface; it does not falsely promise the 0.1.20 blind-tested Demo milestone.
- **Persistence:** Strategy compiles to already persisted price and auto-restock records; restored saves are not overwritten and schema remains v6.
- **Type consistency:** `StorePricingPreset`, `StoreStockingPreset`, `StoreStrategyPlan`, `StoreStrategyService`, `StoreEconomyAnalysis`, and the three `ManagementSection` values are used consistently across tasks.
- **Placeholder scan:** The plan contains no TBD/TODO steps; every implementation task names concrete files, APIs, tests, commands, and expected outcomes.
