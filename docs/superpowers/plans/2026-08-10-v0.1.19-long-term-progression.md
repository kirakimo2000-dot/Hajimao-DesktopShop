# v0.1.19 Long-Term Idle Progression Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the current investment loop into a durable idle-incremental progression foundation spanning first contact, completed business days, repeated offline returns, multi-store capital allocation, and commercial-street growth without adding speed controls or maintenance-heavy systems.

**Architecture:** Keep progression as a read-only projection over existing business, investment, growth, store-catalog, and day-report snapshots. Extend the existing investment service to compare opening a store with improving an existing store, route every action through existing commands, and keep long-run simulation policies in tests rather than production. Add no second currency, prestige reset, daily-login reward, duplicated scheduler, or new management section.

**Tech Stack:** .NET 10, C# 14, WPF/MVVM, xUnit, existing `BusinessSession`, fixed-time `BusinessSimulation`, SQLite schema v6 compatibility.

---

## Scope and file map

- `Application.Business.Progression`: pure milestone and recovery projections; no mutable save state.
- `Application.Business.Investments`: add store-opening candidates to the existing comparable investment contract.
- `Desktop.Services.DesktopGameContent`: remains the single production balance composition point for opening cash, levels and shop unlocks.
- `Desktop.ViewModels.Market`: presents one next long-term goal and one conservative recovery action inside the existing three-section UI.
- `Desktop.Tests.Progression`: owns deterministic 1/7/30-day and repeated-return scenario runners; scenario automation never ships as player logic.
- `docs/design/playable-demo-plan.md` and `docs/roadmap.md`: define first-session comprehension as an entry gate, not a game-length target.

## Self-review

- **Long-term coverage:** first contact, complete days, repeated returns, second/third stores, full street and repeatable weakest-store improvement all have explicit projections or gates.
- **Idle integrity:** no pause, speed, time skip, click income, daily-login cash or alternate offline formula is introduced.
- **Small architecture:** production adds two pure projections and extends the existing investment/strategy commands; automated policies remain test-only.
- **Growth integrity:** no assertion requires “finishing” the game within 30–60 minutes; early comprehension and long-run continuation are independently tested.
- **No placeholders:** every task identifies concrete files, types, commands, assertions and commit boundaries.
